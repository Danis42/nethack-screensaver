<objective>
Make a seeded bench game a pure function of its seed and make it explain how it ended.

Purpose: MEAS-03 (same seed, same game) and the diagnosis data D-09/SURV-03/SURV-04 need. NLE 1.3.0
reads the real clock for moon phase, Friday the 13th and night unless `fix_moon_phase=True`
(RESEARCH Pitfall 5; 2026-11-13 is a Friday inside this phase). The stored `GameResult` has no
death context (RESEARCH Pitfall 11), so starvation, wand and ant deaths cannot be classified yet.
Output: `fix_moon_phase` wiring, an observer that records the last messages, prayers, monster
zaps and end-of-game HP/hunger/depth, a food count and a generic `events` counter dict on every
result, plus slow replay tests that prove determinism end to end.
</objective>

<interfaces>
Contract consumed by plans 01-03 (scripts), 01-05 (A/A), 01-08..01-11 (diagnosis). New
`GameResult` fields, all defaulted so old stored JSON still loads:
- `last_messages: list` - last 8 distinct message-line texts (tty row 0, stripped, non-empty,
  consecutive duplicates collapsed), oldest first
- `prayers: list` - one `[turn, text]` per prayer; `turn` = blstats time at the frame whose
  message line contains `You begin praying to`; `text` = the next 4 distinct non-empty message
  lines joined with ` | ` (fewer if the game ends first)
- `zaps_seen: int = 0` - distinct consecutive message lines matching the word `zaps` that do not
  start with `You` (a monster zapped)
- `hp_at_end: int = 0`, `max_hp_at_end: int = 0`, `hunger_at_end: int = 0`, `depth_at_end: int = 0`
  - from the last observation whose blstats are not all zero
- `food_at_end: int = -1` - edible food items in the inventory after the game, -1 if unreadable
- `events: dict` - non-zero bot counters from `StatsLogger.counters()` (plain ints), `{}` if unreadable
blstats indices used: hitpoints 10, max_hitpoints 11, depth 12 (`DEPTH`), time 20 (`TURN`),
hunger_state 21. `StatsLogger.counters()` returns `{name: int}` for non-zero entries of `_values`;
`StatsLogger.add(name, n=1)` adds n to a registered counter (KeyError for unknown names, like
`log_event`).
</interfaces>
